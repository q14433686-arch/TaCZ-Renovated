## 2. 机制与证据（摘自六线指导，本线逐项复核）

### A · `isSpecial()`

- 1.21.11+ `RecipeManager#finalizeRecipeLoading` 对 `!recipe.isSpecial() && recipe.placementInfo().isImpossibleToPlace()`
  的配方逐条 WARN（vanilla 26.2 `RecipeManager` :102，Renekovski/26.2-mcp）。
  NeoForge 26.2.x / 26.1.x / 1.21.11 的 `RecipeManager.java.patch` 只加 `recipes.order(...)`，**不碰这条 WARN**
  ⇒ Neo 线同样中招。
- 本类返回 `PlacementInfo.NOT_PLACEABLE`（`GunSmithTableRecipe.java` :64–66）且此前未覆写 `isSpecial`。
- `isSpecial=true` 的另一处作用点 `unpackRecipeInfo` 只遍历 `recipe.display()`（本类为空）⇒ 无副作用。
  枪械工作台自身的材料校验走 `TableRecipeManager`，不走 `placementInfo`；JEI/REI 分类同样直接取
  `TableRecipeManager`，不经 vanilla `RecipeManager`。

### C · glock_17 raise 音效

- 本线源码树内 `glock_17.animation.json` 与六线为**同一 blob `82de964`**（`git hash-object` 复核）。
- raise 段引用的 `p24_pi_golf17_stockskel_raise` 不存在于任何 `sounds/` 目录；其余动画的音效均为
  `tacz:glock_17/…` 形态。上游 MCModderAnchor/TACZ 与 Sh1roCu 1.21.1 同样带着这行（上游手误）。
- 应用后 `grep -c golf17` = 0，JSON 解析通过。

### D · `assignCommonEntityPipelinesToHandIfNeeded()` 是 no-op

Iris `IrisPipelines.java` 三条分支（`1.21.11` 含 2025-03-17 `49a7b4a` 起的全部历史、`26.1`、`26.2`）逐字一致：

1. vanilla `ENTITY_*` / `ITEM_*` 管线全部已在静态表预注册为 `assignToMain(ENTITY_CUTOUT, p -> getCutout(p))`，
   `getCutout` 首判 `HandRenderer.INSTANCE.isActive()` ⇒ **逐 draw** 返回 `HAND_*` / `ENTITIES_*`；
   手部 pass 里的抛壳 / 火光 / 枪体本来就走 `gbuffers_hand`。
2. `IrisPipelines.assignPipeline` 对已注册管线直接抛 `IllegalStateException("Shader already assigned")`，
   `IrisApiV0Impl.assignPipeline` 先 `ShaderKey.findBestMatch`（打那几行 WARN）再进 `IrisPipelines.assignPipeline`（抛）；
   我们 `assignPipelineToIrisAny` 把异常吞掉 ⇒ 该调用从未生效，唯一可见效果就是日志。
3. 若某 Iris 版本恰好没预注册（put 成功），后果是把 vanilla 管线钉死成常量 HAND 程序，世界里所有实体 / 物品
   都用错程序 —— 收益为零、风险为全局。

本线额外坑：`GunModClient.onClientSetup` 的 `enqueueWork` 在**启动期**就调一次（不在手部 pass 内），
所以 Neo 玩家日志里那几行 WARN 出现在开光影之前，更容易被误读。

`assignPipeline` 仍保留给 `tacz:pipeline/scope_*` 与 mesh 管线（`assignMeshPipelineToHand/Entity`），本件不动。
