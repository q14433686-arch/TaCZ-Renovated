## 2. 根因与证据

### 2.1 A：枪匠台配方被原版配方书同步

`GunSmithTableRecipe` 实现 `Recipe<SingleRecipeInput>`，`matches` 恒 false、
无展示用 ingredients。原版客户端配方书收到该配方后无法排布，记 WARN
「can't be placed due to empty ingredients」，每次配方书同步复现，玩家
日志中约 250 行刷屏。

API 证据（NeoForge 官方文档 **1.21.11** 版 Custom Recipes 页，2026-09-08
经 `docs.neoforged.net/docs/1.21.11/resources/server/recipes/custom/` 拉取）：
`Recipe#isSpecial()`——"When true, will prevent the recipe from being synced
within the recipe book or awarded on use/unlock"。即 `isSpecial()=true`
后客户端配方书不再收到本配方，WARN 源头消失。`placementInfo()` 返回
`PlacementInfo.NOT_PLACEABLE`（本类已有）管的是「排不进网格」，不阻止
同步，故单独不够。

### 2.2 C：glock_17 `draw` 动画引用不存在的音效

`tacz_default_gun` 源树 `glock_17.animation.json` 的 `draw` 动画尾部带
`sound_effects`，effect 名 `p24_pi_golf17_stockskel_raise` 在资源树内
不存在（`grep -c golf17` 修复前 = 1，仅此一处；修复后 = 0）。Bedrock
动画加载器对未注册 effect 静默跳过，玩家可感知为 draw 动画无声。
参照侧同 blob 已删；本线在源树直接删该 5 行块。JSON 安全性：
`sound_effects` 是 `draw` 内 `bones` 的末位同级键，删块后同步去掉
`bones` 收尾行的尾逗号（否则 JSON 非法），删后 `python3 json.load`
通过、文件其余动画键不受影响。

### 2.3 D：把 vanilla 常用 entity/item 管线钉到 Iris hand program

旧 `IrisCompat#assignCommonEntityPipelinesToHandIfNeeded` 在客户端启动
（`GunModClient#onClientSetup`）与第一人称渲染（`GunItemRendererWrapper#renderFirstPerson`，
每帧路径）各调一次，经 `IrisApi.assignPipeline` 把
`ENTITY_CUTOUT→HAND`、`ENTITY_TRANSLUCENT→HAND_TRANSLUCENT`、
`ENTITY_TRANSLUCENT_EMISSIVE→HAND_TRANSLUCENT` 三条 vanilla 管线
钉死到 hand program。Iris 1.10.x 对这三条管线已有静态表 + 按 draw
分派，手动 assign 只产生 `Found perfect program match ...` WARN 并引入
「若某 Iris 版本未预注册则把 vanilla 管线永久钉到 hand program」的
全局风险（参照侧分析）。删除后：

- `IrisCompat` 保留 `assignPipelineToIris` / `assignPipelineToIrisAny`
  / `ASSIGNED_SCOPE_PIPELINES` / `loggedScopePipelineFailure` /
  `assignMeshPipelineToHand` / `assignMeshPipelineToEntity`——
  scope 管线（`ScopeRenderTypes` 11 处）与 mesh 世界/手持管线（
  `PolyMeshGpuRenderer`）仍需要；
- 删除失效 `import net.minecraft.client.renderer.RenderPipelines`
  （该文件内仅被死方法使用）；
- 删除 `ShaderCompat#assignCommonEntityPipelinesToHandIfNeeded`
  façade（其唯一调用点 `GunModClient` 用全限定名，删调用点后
  façade 无引用）；
- 本线**没有**参照侧的 `commonEntityPipelinesAssigned` /
  `commonEntityPipelinesAssignAttempted` 两个一次性标志位
  （二者只存在于 26.1.2 / refab 变体的同名方法里；本线方法本体
  无标志位，守卫语义由共享 `ASSIGNED_SCOPE_PIPELINES` 集承担，
  该集 scope 管线仍在用，保留）。
